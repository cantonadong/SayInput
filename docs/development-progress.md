## 本轮发现并解决的问题

### DPAPI 测试在文件沙箱内失败

现象：受限环境运行完整测试时，5 个 `DpapiCredentialStoreTests` 抛出 `CryptographicException`，错误提示当前线程可能没有加载用户配置；其余 80 个测试通过。

定位：`APPDATA`、`LOCALAPPDATA` 和 `USERPROFILE` 值正常，异常发生在 `ProtectedData.Protect`。在常规 Windows 用户上下文使用相同代码和测试数据运行后，非硬件测试全部通过。

结论：这是执行沙箱无法访问当前 Windows 用户 DPAPI 密钥配置造成的环境失败，不是代码回归。DPAPI 相关测试必须在正常用户上下文运行，不能通过改用明文、机器级密钥或跳过安全测试来规避。

### 保存后立即退出可能丢配置

原流程先调用 `StopAndDrainAsync()`，再等待设置窗口的活动保存。若保存仍在 `runtime.SuspendAsync(true)` 中、尚未进入配置写队列，写队列会先被标记停止，随后保存被拒绝并被 UI 捕获。

修复：退出顺序改为等待托盘切换、等待活动保存、封闭并排空写队列，然后停止测试、预热和运行时。新增顺序回归测试。

### 剪贴板暂时占用导致回退直接失败

原实现仅在恢复剪贴板时捕获一次 `ExternalException`，读取、设置和手动复制遇到剪贴板占用会立即失败。

修复：对剪贴板读写加入统一的有限重试；连续失败 5 次后仍抛出原异常，避免无限阻塞。新增“第三次成功”和“第五次停止”测试。

### 真实火山引擎实验被本机网络策略阻断

用户授权使用仓库根目录下被 `.gitignore` 排除的 `key.txt` 做真实调用。文件不是纯 key，而是“中文标签＋全角冒号＋末尾 ASCII API Key”；实验工具必须只提取末尾连续可打印 ASCII token，且不得回显、写入日志或文档。正式应用设置界面仍应填写纯 API Key。

2026-09-15 实验结果：`openspeech.bytedance.com` DNS 解析正常，`Test-NetConnection` 对 443 端口成功；临时 .NET 8 WebSocket 最初被 SimpleWall 以 `SocketException 10013` 拒绝。用户放行正式 EXE 并按全局规则完全退出、重启后，应用到达火山引擎。官方四种流式 Resource ID 探测确认：该 API Key 未开通 1.0 小时版和并发版，已开通 `volc.seedasr.sauc.duration`，与用户提供的 LazyTyper“流式识别 2.0”信息一致。配置已通过正式设置界面保存，API Key 由当前 Windows 用户 DPAPI 加密；随后全新进程不读取 `key.txt`、仅使用已保存配置再次连接成功。

## 可复用经验

- Windows DPAPI 的测试结论必须结合用户配置是否真正加载来判断。先用相同命令在正常用户上下文复现，再决定是否改代码。
- 关闭异步应用时，先等待所有可能产生写入的上游任务，再关闭写入入口并排空队列。只等待队列中已有任务无法覆盖“已开始但尚未入队”的操作。
- 剪贴板是共享且易被短暂锁定的系统资源。读取、设置、清空和恢复都应使用相同的短时有限重试，并保留最终失败信号。
- `SendInput` 返回部分成功时，不能自动切换到完整文本的备用注入，否则用户会得到重复或拼接文本；应报告失败并保留可恢复文本。
- 语音服务的 utterance definite 不等于整个会话完成。只有客户端发送音频结束后收到的 terminal 帧才能结算 final。
- 真实硬件、云端和跨应用体验不能用模拟测试替代。自动测试负责协议、边界和生命周期，人工验收负责麦克风、网络、焦点和目标应用兼容性。
- 当前仓库跟踪生成文件，运行测试或发布会产生大量状态变化。提交时应逐项暂存源码、测试、文档、脚本和有意发布的产物，避免 `git add -A`。

### 本轮可复用经验

- 精灵图的画布分区与可见图形中心是两个概念。状态栏小图标对 1 像素偏移很敏感，应以 alpha 内容包围盒对齐，而不是只按整图宽度或人工估算步长切片。
